# S2 — Data flow + State ownership + Invalidation + Event system + the controls-malfunction root

*Cold architectural verdict, 2026-06-09. Theme: who owns/mutates state, whether invalidation is coherent and load-bearing, whether the event surface is real, and the root cause of "basic controls malfunction." Every claim is anchored to a first-hand code finding (A2/A4, all `file:line`-verified) cross-referenced against an external authority (B3 MapLibre — the direct peer; B4 deck.gl/three.js — the WebGPU/TS siblings; B5 engineering principles). Nothing below is asserted unless an A* finding and a B* authority both support it.*

---

## 1. COLD VERDICT (one paragraph)

**NO — this axis is not sustainable as-is for a 5-year / 3D-tiles / 4D horizon, and it is the axis most likely to keep producing the "it compiles, unit-tests pass, controls still malfunction" bugs the owner is angry about.** The state model is a single god-object (`XGISMap`, 3431 LOC, ~10 unrelated responsibilities, ~55 members exposed by-reference to satellite controllers — A2 §1) around which every actor — gesture controller, render loop, render passes, async callbacks — reads and *writes* camera/scene state, so the data flow is a star of mutable shared references, not the unidirectional/diffed pipeline both peers are built on (A2 §4 vs B3 §5, B4 §1.1). The invalidation system that should make this safe is **built, tested, and inert**: a clean 8-domain dirty bitset where 7 of 8 domains are write-only and *nothing* in production reads them to gate a frame (A2 §2) — exactly the "single coarse dirty bit + missing per-domain flags" failure MapLibre's `_styleDirty/_sourcesDirty/_placementDirty` split exists to prevent (B3 §5) and deck.gl's per-attribute invalidation refines (B4 §1.4). The event surface is MapLibre-shaped and the single-vantage emission is genuinely good (A2 §3), but the camera verbs behind it are stubs — `easeTo`/`flyTo` are `jumpTo` aliases that fire `movestart`/`move`/`moveend` in one tick (A2 §3) — which *is* the visible controls malfunction, and the input layer is projection-blind (returns `null` for disc/globe picking) and gesture-jittery (no pinch hysteresis) (A2 §3). It renders today; it does not have the structural bones to carry incremental invalidation, temporal/4D data, or a trustworthy event/animation cadence without first fixing ownership and making the dirty system load-bearing.

**Sustainability score for this axis: 2 / 5** (concurring with A2's independent verdict; A4 independently scores the test-architecture sub-axis 3/5 because the *design* of the inert subsystem is clean even though its adoption is absent).

## 2. ROOT CAUSES (not symptoms)

The visible failures (teleporting `easeTo`, null picking on globe, label flicker, re-arm/dropped-frame bugs, thermal busy-loop) are surface expressions of **four structural roots**:

### Root 1 — There is no single owner of state; `XGISMap` is a god-object that "decomposition" relocated rather than decoupled.
`XGISMap` co-locates ~10 separate concerns and the three "satellite" controllers (`interaction-controller`, `camera-controller`, `render-loop`) do not *own* state — they borrow the map's fields by reference and reach back in (`render-loop` reaches `host.X` **89 times**, 49 in `label-pass` alone) (A2 §1, §4). The file headers admit it: *"BEHAVIOR + PUBLIC API IDENTICAL — moved verbatim… only the dependency wiring changed"* (A2 §1). This is the exact anti-pattern both peers name: MapLibre's sustainability rests on **single owner per concern** — `Bucket` owns geom→buffer, `Style` owns the document, `SourceCache` owns tile lifecycle, no god-object spanning concerns (B3 §10.2); deck.gl/three.js both **reject the god-renderer** via per-layer lifecycle / Core-Shader-Engine layering (B4 §3 anti-patterns). B5 (c) gives the discriminator: a 3431-LOC god-file *is* a real SRP violation worth fixing — but the cure is **named seams with concrete collaborators**, not an interface per concern (B5 (b) Rule of Three).

### Root 2 — Two parallel write paths to camera state make the mutation record structurally incomplete.
The gesture lane calls `camera.pan/rotate/zoomAt/pitch=` **directly**, touching neither `_ops` nor `_dirty`; only the programmatic setters dispatch ops (A2 §4). The render loop *also* writes camera every frame (`azimuthalProjType`, `globeMode`, `projType`, `maxZoom`, plus NaN-reset/clamp/wrap of `centerX/Y/zoom/bearing/pitch`) (A2 §4). So the op-log/dirty bitset can never be a complete record of what changed, and the only reliable convergence point is a per-frame by-value camera diff (A2 §2, §4). This is the **opposite** of both peers' contract: MapLibre funnels *every* state change through a single `_update()` entry point that sets the specific dirty flag (B3 §5); deck.gl makes the scene a pure function of (style, viewport, data) recomputed and diffed, never mutated in place by the render path (B4 §1.1, and B4 §3 row 12 explicitly *rejects* three.js's mutable-scene-graph-as-truth precisely because "props mutate without the framework knowing → stale frame / leak").

### Root 3 — The invalidation system is inert; the real gate is a legacy boolean + hand-rolled diff, and there are 4 redundant camera-state caches with no shared generation counter.
`state/dirty.ts` is a clean 8-domain bitset, fully wired on the producer side (~15 `_ops.dispatch` sites, `invalidate()` tags all 8), but the **only** production consumer is one LABEL-domain read in `label-pass`; the other 7 domains are write-only (A2 §2, verified by grep). The code says so: *"WRITE-ONLY back-compat wrapper… no per-frame consumer reads it to skip yet"* and *"Still INERT: `shouldRenderThisFrame()` reads `_needsRender`, not `_dirty`"* (A2 §2). Meanwhile the same five camera scalars are mirrored into **four-to-five independent shadow caches** (`_lastSig*`, `_evtSig*`, `camera._cache*` + `_ecefCache*`, `_prevLabelDispatchSig`) each with its own hand-maintained invalidation and **no shared generation counter**, so they can silently desync — already flagged for a hypothetical future `centerX` setter (A2 §1, §3). This is precisely the gap B3 §5 names as MapLibre's highest-value transferable pattern (split the single dirty bit into domains so each stage skips cheaply and "re-arm" bugs go away because the landing callback sets the *specific* domain), and that B4 §1.4 refines to per-attribute granularity. The manual-memoization-with-no-generation-counter pattern is the textbook desync trap B5 (b) warns abstraction-without-a-real-seam produces.

### Root 4 — Camera verbs and the input layer are façades; the event *cadence* and *coordinate* contract are therefore wrong, not just thin.
`easeTo`/`flyTo` discard `duration/curve/easing` and alias to `jumpTo` (A2 §3) — *"X-GIS has no transition infra yet."* Consequence: an animated camera move fires its entire `movestart→move→moveend` sequence in one tick, so any host driving overlays/throttles off the event cadence sees a teleport — **this is the "basic controls malfunction."** This is exactly the demand-render footgun B4 §2.2 documents from three.js: *animations need a pre-emptive `invalidate()` and must keep the flag alive each frame*; without transition infra + per-frame re-arm there is no glide to emit events across. The input layer compounds it: `clientToLngLat` returns Mercator-only and `null` for disc/globe (A2 §3), and pinch-rotate has no hysteresis so finger jitter spuriously rotates during a pure zoom (A2 §3) — the unproject/coordinate correctness that B3 §5 and the camera-control contract assume is simply absent on non-Mercator surfaces.

**Why these four are *roots* and not symptoms:** every visible bug traces to one of them. Teleporting controls = Root 4 (no transition infra) + Root 3 (no per-frame animation re-arm domain). Dropped-frame-after-async-tile-land = Root 3 (the LABEL domain is the only consumer; a glyph/tile arrival has no specific domain to set and no funnel to schedule a frame — the exact B4 §2.2 / §3-row-8 "every async arrival must re-invalidate" invariant is unenforced). Label flicker across zoom = Root 1+3 (no cross-tile identity owner, label logic entangled in a 980-line method, no `_placementDirty` multi-frame convergence — A4 §2b, B3 §6). Near-pole tile/unproject corruption = a *second source of truth for latitude* (`centerLatDeg` vs `mercatorYToLat(centerY)` deliberately diverge past 85.05°, A2 §1), a literal two-authorities-for-one-quantity defect that B3 §10.3 ("the spec is the *sole* authority, forbid parallel sources of truth") and B5 (b) both forbid.

## 3. TARGET STATE (what "good" looks like, grounded in what the peers actually do)

The target is **not** a rewrite and **not** an ECS (B5 (a) is explicit: X-GIS's core data is spatial = ECS's documented weak spot; a generic entity/query runtime is the speculative abstraction to avoid). It is the MapLibre/deck.gl *contract* shape, reached by strangler-fig migration:

1. **One `_update()` funnel + a load-bearing per-domain dirty system.** Every mutation site — *including the gesture lane* — routes through a single scheduler that sets the specific `DirtyDomain` and requests exactly one frame; the frame gate reads the bitset, not a boolean (B3 §5: `_styleDirty/_sourcesDirty/_placementDirty` + `_update` + idle convergence). The four redundant camera caches collapse into one camera generation counter that the (now-consuming) bitset reads (closes A2 §1 Root 3). "Good" = the dirty system *gates* frames and *stops requesting them when idle* — which is simultaneously the correctness fix (re-arm bugs vanish), the thermal fix (no busy loop; B4 §2.1 demand-render), and the testability fix (an observable `idle`).

2. **State has single owners; the render path is a pure consumer.** Decompose `XGISMap` along named seams toward concrete collaborators (B5 (b): Rule of Three, not an interface per concern). The render passes stop *writing* `show.resolved*` and `camera.*` (A2 §4) and become pure readers of a scene that is a function of (style, camera, data) — the deck.gl reactive model (B4 §1.1) and MapLibre's "renderer is a pure function" (B3 §1). 4D falls out additively: a temporal source is "just" a source whose covering-tile/cache key includes a time coordinate, and layers reference it unchanged (B3 §2 4D-note) — but *only* if ownership is clean first.

3. **A real event + transition contract.** Keep the genuinely-good single-vantage `_processCameraEvents()` diff (A2 §3, §5) and put real interpolation behind `easeTo`/`flyTo` so the move-event cadence streams across the animation (B4 §2.2: pre-emptive invalidate + per-frame re-arm). Adopt MapLibre's `Evented` mixin discipline near-verbatim — bubbling parent chain, error-events-never-silent — as a ~200-LOC, zero-GPU-coupling module (B3 §4).

4. **An async-arrival invariant + an enforcing test.** Every async producer (tile decode, glyph atlas, sprite, data load) ends by arming the specific dirty domain; a regression test fails if a producer lands without invalidation (B4 §3 row 8, §4.4). This is the structural cure for the recurring re-arm/dropped-frame bug class.

5. **Projection-complete, jitter-stable input.** `clientToLngLat` returns a real lng/lat for every projection family (per-projection inverse), and pinch-rotate gets a hysteresis dead-band so jitter during a pure zoom doesn't rotate (A2 §3). This is correctness the event contract already assumes.

## 4. RECOMMENDATIONS (each with rationale / evidence / risk / blast-radius)

### R1 — Make the dirty system load-bearing: single `_update()` funnel, per-domain gate, route the gesture lane through it.
- **Rationale:** The single highest-leverage structural fix. It converts already-built-but-inert infrastructure into the mechanism that fixes re-arm bugs, thermal cost, and testability at once. Today every setter does quadruple bookkeeping (mutate + `_needsRender` + push Op + tag domains) and only the boolean drives a frame — pure overhead presenting a false "domain-routed invalidation" affordance (A2 §2).
- **Evidence:** A2 §2 (7/8 domains write-only; gate is `_needsRender` + `_lastSig*` diff), A2 §4 (gesture lane bypasses `_ops`/`_dirty`); B3 §5 (the exact pattern — `_update` funnel + per-domain flags + idle convergence — named MapLibre's "highest-value pattern to copy exactly"); B4 §1.4 / §2.2 (per-attribute invalidation + demand-render coalescing flag).
- **Risk:** MEDIUM. The gesture lane currently relies on the per-frame value diff to converge; routing it through `_update` must not drop a mutation or double-schedule. Mitigate with B5 (c) Branch-by-Abstraction behind a flag (old value-diff path stays live until the bitset gate is proven byte-identical via the golden matrix).
- **Blast-radius:** HIGH (touches every setter, the gesture controller, `shouldRenderThisFrame`, and the four caches) — but it is *additive-then-switch*, so each commit stays green and revertible.

### R2 — Collapse the 4 redundant camera-state caches into one generation counter the bitset reads.
- **Rationale:** Four hand-maintained shadow copies of the same five scalars, no shared generation, already flagged to desync on a future `centerX` setter — this is the manual-memoization trap that produces "fix-here-breaks-there" (A2 §1, §3).
- **Evidence:** A2 §1 (`_lastSig*`, `_evtSig*`, `camera._cache*`+`_ecefCache*`, `_prevLabelDispatchSig`; audit ⑩ B6 fragility note); B3 §10.2 (single owner per concern); B5 (b) (abstraction must remove a real current bug class — this one does).
- **Risk:** MEDIUM. The MVP-matrix cache is performance-critical; a generation-counter check must be as cheap as the current by-value compare. Verify with the existing `_shader-math-parity`/MVP gates.
- **Blast-radius:** MEDIUM (camera.ts + map.ts cache sites; ~59 grep-hit lines per A2 §1). Naturally folds into R1.

### R3 — Build real transition infra behind `easeTo`/`flyTo`; fix the event cadence.
- **Rationale:** This is the literal "basic controls malfunction" — a typed, present API that teleports and emits a one-tick event burst (A2 §3). It is also a precondition for `_placementDirty`-style multi-frame label-fade convergence.
- **Evidence:** A2 §3 (`easeTo`/`flyTo` = `jumpTo`, params discarded; one-tick `movestart/move/moveend`); B4 §2.2 (animations need pre-emptive `invalidate()` + per-frame re-arm — the demand-render footgun, documented from three.js); B3 §4 (camera event taxonomy is the stable contract hosts depend on).
- **Risk:** LOW-MEDIUM. Transition infra is well-understood (easing + per-frame interpolation + the R1 re-arm). Risk is interaction with R1's idle convergence (an animating camera must keep the loop alive — exactly the B4 §2.2 invariant).
- **Blast-radius:** MEDIUM (camera-controller + the animation clock `_startTime`/`_elapsedMs` already present; gated on R1's funnel).

### R4 — Codify the async-arrival → invalidate invariant and add an enforcing regression test.
- **Rationale:** The dropped-frame-after-async-land bug class (glyph PBF / tile landed) is *structural* to demand-render, not incidental — it recurs because there is no rule and no test (A4 §2b label-pass calls `host.markLabelDirty()` from one async callback, but that is one ad-hoc site, not an invariant).
- **Evidence:** B4 §2.2 + §3 row 8 + §4.4 (three.js texture-load footgun = "every async arrival MUST re-invalidate"; add a test that fails if a producer lands without invalidation); A2 §2 (LABEL is the *only* domain with a live producer→consumer loop today).
- **Risk:** LOW. Pure additive discipline + one test; no behavior change to existing paths.
- **Blast-radius:** LOW (every async completion handler gets one line; one new test). Best done *with* R1 so each producer arms a specific domain.

### R5 — Decompose the `label-pass` god-method and establish cross-tile symbol identity, gated on the dirty loop.
- **Rationale:** `label-pass.execute()` is a single ~980-line method with 12 inline closures (point/line/icon/dedupe/projection interleaved) — a god-object hiding behind the clean `RenderPass` interface (A4 §2b). Its size correlates with the recurring label-bug history (CJK box-out, bearingY collapse, anchor parity, world-copy gaps), because a change to one sub-phase has no local blast radius. The deeper root is no persistent cross-tile identity layer, so every zoom-cross is a fresh placement with no memory.
- **Evidence:** A4 §2b (1065 LOC, 980-line method, 12 closures, 13 perfMark phases); B3 §6 (the MapLibre ownership split — `CrossTileSymbolIndex` = identity-across-tiles, `Placement` = this-frame collision, `Tile` = latest-data; "the most valuable single thing to copy," gated on the dirty-flag loop for `_placementDirty` fade convergence); B5 (c) Sprout (extract into new tested units, never edit the monolith in place).
- **Risk:** MEDIUM-HIGH. Label placement is correctness-sensitive and currently has no automated raster gate (A4 §3a: 260/262 runtime tests are CPU-only, the one raster gate is local/manual). Decomposition without a golden-master image matrix risks silent regressions — so this is **gated on a real-GPU golden matrix existing first** (B5 (d), and the cross-cutting test-void finding A4 §3).
- **Blast-radius:** HIGH within the label subsystem; contained from the rest by the clean pass interface. Lower priority than R1-R4; do it after the invalidation loop and the visual gate are in place.

### (Sequencing) R1 → R2 (folds in) → R4 (folds in) → R3 → R5. R1 is the keystone: R2/R3/R4 all attach to its funnel, and R5 needs both R1 (for `_placementDirty`) and the cross-cutting real-GPU visual gate.

## 5. EXPLICIT UNCERTAINTIES / DISAGREEMENTS

1. **Is the inert dirty/op subsystem defensible as a staged migration, or is it net-negative today?** A2 §2 calls it "infrastructure paid for but not yet earning — defensible as a staged migration, indefensible if it ships to v1 in this state." I concur with the tension but flag the disagreement: the comments frame it as roadmap-staged (S14/S16), yet B3 §5 and B4 §1.4 both treat per-domain invalidation as *table-stakes*, not advanced. **Uncertainty:** whether the bitset's current shape (8 fixed domains) is even the right granularity, or whether deck.gl's per-attribute / `dataRange` sub-slice model (B4 §1.4) is the truer target — the evidence supports *that* invalidation must become load-bearing, not *which* granularity wins. Resolving this needs a decision the A* files don't make.

2. **Whether routing the gesture lane through `_update()` is cheap enough.** A2 §4 establishes the gesture lane bypasses the op system; B3 §5 says route everything through one funnel. But neither A2 nor B3 measures the per-gesture-event cost of op-dispatch on a high-frequency drag/pinch stream. **Risk of being wrong:** if op-logging every pointer delta is too expensive, the funnel may need a fast-path that still tags the domain without recording an Op. Unresolved by the evidence.

3. **The op-log itself.** `OperatorBus` is capped at 256 and read by nothing in production (`lastOp`/`depth` are "for tests / future undo," A2 §2). B3/B4 give no authority for an op-log/undo system in a *renderer* (it's a doc/editor pattern). **Disagreement with the implied roadmap:** I see no external-authority support for the op-log earning its keep in a map renderer; the dirty *bitset* is well-supported (B3 §5, B4 §1.4), the op-*log* is not. It may be speculative abstraction per B5 (b) — but the A* files don't conclude this, so I flag it as an open question rather than a finding.

4. **deck.gl's "recreate every layer every change" model vs X-GIS's large binary tile buffers.** B4 §1.1 / §3 (Where transfer is limited) warns the reactive recompute model assumes shallow-compare-friendly props; X-GIS's big binary buffers must use the binary-attribute escape hatch or the model over/under-invalidates. **Uncertainty:** how far the deck.gl descriptor model can be adopted for *tile* geometry (vs the camera/layer control plane) is genuinely open — I recommend the model for the control plane and dirty discipline, not as a wholesale rewrite of the VTR tile path, and the evidence (B4's own caveat) supports that caution rather than a clean answer.

5. **Cross-cutting dependency this theme cannot resolve alone:** R5 (and validating R1-R3 don't regress rendering) is blocked on the real-GPU visual-regression matrix being an *automated gate*, which A4 §3 proves does not exist (4 CI specs, none paint a pixel; the matrix is local/manual). Until that exists, every recommendation here is verified only "procedurally" — the same human-discipline gap A4 §4 names as why bug classes recur. This is owned by the test-architecture theme, but it gates the safe execution of S2.

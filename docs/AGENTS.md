# docs/

## Purpose
Internal engineering documentation for the X-GIS project. These Markdown files record architectural decisions, coordinate-system contracts, roadmaps, and implementation plans that span multiple packages. They are not published to the website; they exist to orient contributors and preserve design rationale across sessions. The most critical file is `COORDINATES.md`, which defines the canonical coordinate-space contract that all tile-pipeline code must honour.

## For AI Agents

### Working In This Directory
- `COORDINATES.md` is the **authoritative contract** for the tile pipeline coordinate system. When any code changes affect clipping, simplification, projection, or sub-tile generation, verify compliance against this document's invariants and checklist.
- These files are READ-ONLY design documents for most sessions. Do not edit them unless explicitly asked to update a roadmap or decision record.
- When the implementation of a planned phase is complete, update the relevant roadmap file to mark the phase done (noting the commit hash), consistent with the pattern used in `WEBGPU_ROADMAP.md`.
- `dsfun-refactor-plan.md` notes that the vertex format change is an atomic refactor — do not start partial implementation without a plan to complete it in one session.

### Testing Requirements
- No runnable tests in this directory. The cross-path invariants described in `COORDINATES.md` are enforced by `runtime/src/__tests__/tile-cross-path-invariants.test.ts`.

### Common Patterns
- Roadmap docs use a consistent phase structure: phase name, status (DONE / pending), commit hash when done, and concrete subtask list.
- The coordinate-space table format (`LL`, `MM`, `DLM`, `SP`) is the canonical vocabulary — use these abbreviations in code comments and commit messages when referring to coordinate spaces.

# TypeShade — the agent era: pre-mortem and survival strategy (2026-09-07)

**Owner's question, verbatim:** _"Tell me why this library will NOT survive in the AI-agent era, and how to solve it — that is the strategy."_
**Method:** four adversarial lenses (agents-as-authors · porting economics · is-verification-commoditised · distribution), each pre-mortemed from 2029, each then put through an independent verification pass that fetched every external source and re-ran every measurement. **8 of 42 checked claims were refuted, including two of the lenses' own headline numbers — those corrections are in §2 and are carried into every number below.**
**Companions:** `2026-09-07-typeshade-strategic-plan.md` (**SP**) · `2026-09-07-shader-dsl-standalone-product-strategy.md` (**PS**) · `2026-09-01-shader-dsl-improvement-direction.md` (**DD**) · `2026-09-07-typeshade-go-to-market.md` (**GTM**). Where this disagrees with them it says so and shows the evidence.
**Discipline (SP §15):** every number carries a fetched URL dated 2026-09-07, a `file:line`, or the tag `(from memory)`.

## 0. Executive summary

**Why it dies.** TypeShade is priced as an authoring convenience, and both of its headline claims are already commoditised by free, better-distributed things. Porting: `naga-cli 30.0.1 --profile es300` translated **92 of 116** entry points of X-GIS's own baked WGSL corpus and **90 compiled on a real WebGL2 context** — **77.6% of the twin-shader tax refunded, today, by a browser vendor's tool, for free** (measured 2026-09-07, §2.2). CPU execution: `wgsl_reflect` ships a WGSL CPU executor at **277,311 weekly downloads** (npm, 2026-09-07), so SP §1.3 S1's "no comparable library ships one" is no longer defensible as written. Meanwhile the input language TypeShade demands is one no model has a corpus for — **355 exported symbols** (`shader-dsl/src/api-surface.test.ts:37`) against a measured ceiling of **47.94% valid low-frequency API calls even with the docs in context** (CloudAPIBench) — and its distribution channel is install-ranked and already occupied: the same TypeGPU subject earns **52,017 installs inside a third-party bundle against 1,320 from its own maintainer** (skills.sh, 2026-09-07), while `typeshade.dev` returns no HTTP response at all and npm `typeshade` is a `0.0.0` placeholder. The 2029 obituary is not "agents wrote raw WGSL". It is: _a correct compiler nobody could point an agent at, defending a tax a free vendor tool had already refunded._

**The strategy that prevents it.** Stop selling a language; sell a **checker and a gate over the language agents already write**. Five moves, in dependency order: **(1) WGSL/WESL ingestion of an admitted subset, aimed at the 77.6% naga already translates, not at the residue** — the input becomes a `.wgsl` file, so for every construct v1 admits the API tax, the hallucination surface and the migration cost go to zero at once, and **everything else is named by a coded diagnostic, not silently mis-lowered** (§3.1). The claim is "TypeShade checks the WGSL shapes it admits and names the rest", never "TypeShade ingests WGSL". **(2) Move the proof from consistency to rendered truth** — a package-owned two-backend frame differ, plus the divergence corpus published as a suite others run, because a proof nobody can falsify is a badge (§3.2). **(3) A CLI-first agent surface** — `typeshade check|emit|reflect|diff` with coded `SD####` fixes, a `SKILL.md`, a Context7 listing; MCP last and llms.txt as an hour's work, because both have measured near-zero yield **as discovery channels** (§3.3). **(4) Enter through someone else's bundle**, not your own listing (§3.4). **(5) Sell the gate** — a PR check on agent-written shader diffs, which grows with agent volume instead of expiring with WebGL2 (§3.5). And **run the benchmark** (§3.6) rather than asserting the agent claim: it is the only instrument that says whether any of this worked.

### The top five, one paragraph each

**F1 — the zero-corpus API tax (0.85 × 5).** The failure is not refusal, it is confident confabulation. TypeShade's surface is TypeScript-shaped but not TypeScript-semantic — `.assign` instead of `=`, `Let` vs `Var`, a value-combinator `when` beside a statement `If` — and at least two of its documented idioms are **type-correct and silently wrong**: a bare `rawStmt(...)` inside an `fn` body "is a silently discarded expression (the returned `Stmt` is never pushed, so nothing is emitted)" (`shader-dsl/AUTHORING.md:187-188`), and `.mod` is trunc-mod while the free `mod()` is floor-mod, differing only on negative operands (`AUTHORING.md:332-341`). That is exactly the class the type channel cannot see, so the plan's own agent argument does not reach it. The standard fix is refuted as a plan, not merely uncertain: CloudAPIBench measures GPT-4o at **38.58% valid low-frequency API invocations, rising only to 47.94% with documentation-augmented generation** (arxiv.org/abs/2407.09726, fetched 2026-09-07).

**F2 — the ranked, occupied channel (0.85 × 5).** Agent discovery is winner-take-most and ranked by installs. TypeGPU ships an official Skill and an experimental Runtime Inspector MCP that "helps agents catch runtime errors and inspect generated WGSL code" plus a 66,031-byte `llms.txt` (docs.swmansion.com/TypeGPU/tooling/ai-tools/, fetched 2026-09-07); three.js publishes a 132,070-byte `docs/llms-full.txt`; PixiJS publishes 52 official skills. TypeShade publishes none, `skills.sh/api/search?q=typeshade` returns 0 results, `typeshade.dev` returns curl exit 000 and `typeshade.github.io` 404s (all measured 2026-09-07). Entering a ranked list at zero in 2027 is a materially harder problem than publishing docs was in 2019 — and the ceiling for a self-listed skill is visible: MapLibre's own ten official skills top out at **660 installs** against 4,366,094 weekly npm installs.

**F3 — the tax collapses (0.75 × 5).** SP §7 prices a real option on hosts finishing their ports. The option is already ~three-quarters exercised by someone else: over X-GIS's own production corpus, naga translated 92/116 entry points and 90 compiled on WebGL2 — **77.6% free, with zero authoring change and no dependency to adopt** (§2.2). Every one of the 24 refusals is `Features(BUFFER_STORAGE | DYNAMIC_ARRAY_SIZE)` on retained/instanced GPU-driven renderers, which is a platform fact, not a naga defect: on the WebGL backend `max_storage_buffer_binding_size: 0` (docs.rs/wgpu/latest/wgpu/struct.Limits.html, fetched 2026-09-07). And the population number the strategy repeats most — 64% adapting shaders — comes from a survey that **contains no question about AI, LLMs or agents at all** (khronos.org/blog/shader-ecosystem-survey-results-2026, verified by fetch 2026-09-07). It measures a pre-agent cost.

**F4 — a vendor takes the slot (0.70 × 5).** Vercel Labs' `vgpu` — "the WebGPU library designed for agents" (vgpu.sh, fetched 2026-09-07) — was first published to npm on 2026-05-26 and is at **49,779 weekly downloads** ten days before this document was written. It ships `.wgsl` files that "import and export like TypeScript modules" resolved through typed WGSL reflection, a Dawn-backed `vgpu/node`, a `vgpu/mock` "deterministic software adapter … built for tests and CI", `npx vgpu check`, `llms.txt` + `llms-full.txt`, and a hosted read-only MCP server. That is SP §13 D4's entire agent programme, shipped, with distribution. What `vgpu` has **not** got, checked explicitly on both its README and its site: no GLSL, no WebGL2, no oracle, no golden, no differential. That gap is the whole opening — and it closes the day Vercel decides to fill it.

**F5 — ingestion asymmetry (0.80 × 4).** The migration path runs the wrong way. Everything an agent already holds — a `.wgsl` file, a GLSL shader, a Shadertoy snippet — is text naga and Tint accept as **input**. TypeShade accepts only TypeScript written against a combinator surface with 1,608 lines of `AUTHORING.md` to learn, whose §12 "Migrating a GLSL shader" is a hand-written vocabulary map for a human, not a tool. Measured contrast on the same corpus, same session: naga ingested 525,029 bytes of WGSL in one shell loop; TypeShade's ingestion cost for the same corpus is a full rewrite. The repo has deferred the fix twice with stated reasons (DD D7.5; owner decision 7, 2026-09-02), which means re-opening it is a decision to take deliberately (§6 D8), not to drift past.

### 3.1 S1 — WGSL/WESL ingestion (the highest-leverage inversion)

**Decision to take:** re-open DD D7.5 / owner decision 7 (DD:487, DD:597) deliberately — and name **both** halves of its precondition, because the earlier draft of this section argued only one. It reads: a WGSL importer "only after **D6.1** exists (the fuzzer is its oracle) **and** only if a migration corpus appears". The **corpus** half is met by construction — every agent writing WGSL is the corpus. The **D6.1** half is **not met**: the fuzzer is a DD Wave 1 item sized (M) (DD:447), and Wave 1 has not started — Wave 0 is the last row marked COMPLETE (DD:498-499), while the importer sits in Wave 4 behind the gate "API surface frozen by tag" (DD:502). **S1 therefore re-orders DD's Wave 4 ahead of an unbuilt Wave 1 item, and that re-ordering is the decision, not a detail.** D6.1 is priced as its own row below and carried into D8's option (c); without it an admitted construct's lowering has no oracle that can tell right from plausible.

**Aim it at the 77.6%, not at the 22.4%.** F3 (`:26`) is right that the residue — storage buffers on GPU-driven renderers — is commercially inert for the beachhead, which never uses it, so aiming a 6–10-week importer there would buy nothing. v1 is **not** a rival translator for naga's refusals. It is a **checking layer over the shapes naga already translates**: an agent's `.wgsl` goes in, TypeShade type-checks it, reflects its std140 layout, runs it on the CPU oracle, emits its own GLSL ES 3.00 and proves the two emits agree. naga translating the same file is not the competitor, it is the **control arm** — the same role it plays in S6's arm (2). The buyer of the residue, separately: nobody in the beachhead, which is why the residue is a _diagnosis_ (`SD####` naming the construct) and never a promise.

**The admitted subset, v1 — stated so a reader can predict a rejection without running the tool.** Admit: vertex and fragment entry points; `var<uniform>` blocks and `var<private>`; `texture_2d` / `2d-array` / `2d-multisampled` plus `sampler` (`ir/types.ts:76-78`); f32/i32/u32 scalars and vectors, square f32 matrices (`ir/types.ts:65`); user `struct`s; the **13 statement kinds** of `ir/nodes.ts`; the `BUILTINS` intrinsics. Reject **fail-closed**, with a coded diagnostic naming the construct at its `file:line`: storage buffers and runtime-sized arrays, atomics, `var<workgroup>` and barriers, pointers and references, `loop` / `while` / `break if` / `const_assert`, non-square matrices, cube / 3d / depth / storage textures, and anything the IR has no node for. This is the discipline the portable compute tier already uses (`portable: true` declared, never inferred; `SD0110`/`SD0111`). **An importer that silently mis-lowers is worse than no importer.**

**What may be claimed, everywhere it appears.** "TypeShade checks the WGSL shapes it admits and names the rest." Never "TypeShade ingests WGSL", and never that the API tax is _removed_ — it is removed **for admitted files only**, and §0, §3.3's CLI table, §3.7 and §4's scenario A are written to that bound.

**The denominator is unmeasured, and measuring it is the whole point of the spike.** What this report measured is naga's 77.6%, not TypeShade's admitted share. How much of X-GIS's own 525,029-byte baked corpus — and of a sample of agent-written `.wgsl` — falls inside the subset above is **not known**. The 2-week spike (§5.2, D8) measures exactly that against `ir/nodes.ts` and `ir/types.ts`, and the number is the go/no-go: **admit under ~60% of agent-written files first-try and v1 is a demo, not a product** — a fail-closed importer that rejects most of its input removes none of the API tax it exists to remove.

### 3.2 S2 — re-centre on proof, and make it rendered proof

**SP §13 D1(b) — "lead with typed + proven, dual-target as the first proof" — is right and insufficient.** Two amendments, both forced by §2:

**First, the reversal this defence contains, stated rather than smuggled.** §2.4 (`:55`) uses "the real-driver gates are X-GIS scenes" (DD:548; PS:45) to prove the rendering instrument is non-transferable — and S2 then proposes transferring part of it. **S2 re-opens the premise of #1681 / DD §5, and here is why the shader-scoped subset is separable where the scene-driven gates are not.** A scene gate composes a camera, a tile set, a style, a convergence controller and a wall-clock-driven adaptive quality path; none of that is separable, and #2120 is the record of what happens when a gate inherits it. A **shader-scoped** arm composes one module plus a fixture uniform set drawn into an offscreen target — no camera, no tiles, no controller, therefore none of #2120's moving subject by construction. The claim narrows to exactly that: **shader-scoped frame parity ships in the package; scene-scoped rendering truth stays in X-GIS and is not claimed anywhere.** The browser becoming a dev dependency is itself a reversal of "no browser dependency" and is recorded as one — behind an opt-in subpath, runtime dependency count unchanged at 0.

1. **The proof must be about pixels, not about text.** Extract the shader-scoped part of the apparatus X-GIS already runs — headless Chromium on SwiftShader with both backends, chrome-free capture, engine-quiesced settling, the directional DC/D0/D1 ladder (CLAUDE.md §5) — into a package-owned harness over a module plus a fixture uniform set. Output: for any module (or, with S1, any ingested WGSL), a signed diff image and the ladder numbers proving the WGSL and GLSL emits render the same frame. It must inherit this repo's paid-for capture discipline verbatim (`captureMapFrame`/`awaitMapIdle`, never `waitForTimeout`) or the gate hashes its own convergence state (#2120, #2284, #2539). Its runtime dependency count stays 0; the browser is a dev dependency behind an opt-in subpath.
2. **Publish the divergence corpus as the product.** The oracle is copyable; the list of what it caught is not, because a fresh harness that does not know a case exists reports zero, and a zero reads as clean (CLAUDE.md §12). Extract, MIT and toolchain-neutral: integer `/` and `%` semantics (`idiv(7,2)` returned **3.5** in both CPU engines until #2274, fixed in PR #2270 — `core/cpu-runtime.ts:49-58`), u32 wrap, `x/0`, `x%0`, `min(NaN,1)`, clamp order, GLSL ES 3.00's integer-only `%` (`AUTHORING.md:329-341`), std140-vs-std430 padding, the MSAA and storage fail-closed shapes, and the fp64 cancellation cases. Score naga, Tint, `vgpu`, TypeGPU and any agent-built harness against it. This makes TypeShade the **referee**, is citable (which is corpus presence), and is the only artifact here a browser vendor has a reason to care about — DarthShader's 39 faults across Chrome/Firefox/Safari shader translators, 15 with Chrome CVEs, establishes that audience.

**Consequence for the landing page (SP §14).** The hero shrinks and gains a concession: state that **77.6% of shaders port free with naga, and name the 22.4% that does not.** An evaluator can rerun that number in an hour with the same commands; a claim that implies otherwise is refutable in public, which is precisely the loss SP §14 says the project cannot take twice. Two lines join the "do not claim" list: never "no comparable library ships a CPU oracle" (§2.6), and never any implication that TypeShade translates better than naga in general.

### 3.3 S3 — the agent-legible product, re-ordered

**Order matters more than contents.** Two of SP §13 D4's three legs are measurably poor; the third has a live competitor precedent. Ship in this order:

**1 — CLI (zero tool-slot, zero schema tax).** The compiler is zero-dependency TypeScript that already type-checks and runs under Node (`shader-dsl/README.md`), so this is packaging, not engineering.

**2 — `SKILL.md`, published to the public skill registries.** Contents: the ten idioms that differ from the model's prior (`.assign`, no `+=`, `Let` vs `Var`, `If`/`when`, `Loop`'s counter binding, `matchEnum`), **the two silent traps named explicitly** (`rawStmt` in an `fn` body; `.mod` vs `mod()`), the `SD####` codes with their fixes, and the check-fix-recheck loop through the CLI. Budget the **recurring** cost the plan does not: a skill must be re-published on every breaking release or it teaches a dead API — the competitor's skill is explicitly version-pinned ("aligned with Three.js r183+", dgreenheck/webgpu-claude-skill, fetched 2026-09-07). Add that line to SP §11.2.

**3 — Context7 listing** (`github.com/upstash/context7`: **61.7k stars**, fetched 2026-09-07 — the "9,000+ libraries indexed / #1 on MCP.Directory" figures an earlier draft carried are **withdrawn**: neither context7.com nor its rankings page states a library count, and no source was found, so they are not used and KR4.3 does not rest on them). Put the docs path on someone else's high-traffic server instead of your own low-traffic one — **and book this as an unmeasured bet**: the llms.txt evidence below is AI-**search**-crawler log data, and no measurement of _coding-agent_ retrieval through Context7 was found in this study. Its signpost is KR4.3's own reading at month 3, not that evidence. **4 — `AGENTS.md`** in the mirror ("used by over **60k open-source projects**", agents.md, fetched 2026-09-07, sourced there to a GitHub code search `path:AGENTS.md NOT is:fork NOT is:archived`; the same page names Codex, Cursor, Copilot's coding agent, Gemini CLI, Windsurf, Jules, Junie, Amp, Zed, Devin and others). **5 — `llms.txt`**: ship it, size it like TypeGPU's 66 KB, generate it from the API-reference source, and budget **zero belief** in it. **6 — MCP server, last or never**, and booked under retention: the same `check`/`emit`/`reflect`/`diff` verbs, so an agent's edit is rejected with a machine-actionable reason before it reaches a PR. Remove it from the adoption KPI panel.

**And publish the corpus before the reference.** Given a 355-symbol API with no training-data presence, the artifact that reduces hallucination is not a reference but a small MIT set of **complete, compile-verified modules** — each with its emitted WGSL, its emitted GLSL and its gate result attached. Regenerate it in CI or it rots (SP §9 R12).

### 3.4 S4 — distribution: enter through someone else's bundle

The single most actionable measurement in this study: **the same subject, `typegpu`, earns 52,017 installs inside HeyGen's HyperFrames bundle and 1,320 from its own maintainer's repo — 39.4×** (skills.sh/api/search, 2026-09-07). The channel's mass is allocated by inclusion decisions inside Vercel, HeyGen, Unity, Figma and Remotion, not by the quality of a self-listing. Target **one accepted PR** into an adjacent high-install bundle — **and read the numbers at the level they were measured**: what §7 measured is **single skills inside** those bundles, `cloudai-x/threejs-skills/threejs-shaders` at **9,925** and `gamedev-skills/…/shader-programming` at **2,400**, not bundle totals, which were never taken. The bundle-reach thesis therefore rests on the one subject where **both** levels were read — 52,017 for `typegpu` inside HeyGen's bundle against 1,320 for the same subject self-listed — and on nothing else. Candidates: `cloudai-x/threejs-skills` · `gamedev-skills/awesome-gamedev-agent-skills` · `vercel-labs`; or, better, a **host-owned** bundle (`pixijs/` 52 skills · `maplibre/` 10 skills) — which is SP §6.3 rung 3 expressed in the agent channel, and is checkable in a way a docs listing is not.

**A ranking correction for the agent axis.** SP §6.4 ranks MapLibre 1 on human pain; that stands and D2 is settled. But on the agent axis MapLibre already owns its namespace, while **deck.gl has none**: `deck.gl/llms.txt` is a 404, there is no vis.gl-owned skills namespace, and its third-party presence is seven skills at 2–12 installs — one of which is already named `deckgl-custom-layer` (skills.sh, 2026-09-07). The opening there is an **upstream offer to vis.gl**, not a land-grab on an empty query.

**Two blocking prerequisites, both same-day:** replace or unpublish the `0.0.0` npm placeholder, and make `typeshade.dev` resolve. Until then every agent-channel artifact routes to a dead end and confirms "not real".

### 3.5 S5 — sell the gate (needs S1 and S2 to be true)

Package the combination as a pull-request check for a shader change: does it still compile on both targets · did the emitted **meaning** change (`semanticDiff`) · did the rendered frame change and where (S2's differ) · do the WebGPU and WebGL2 paths still agree. **Redefine the buyer** from "a team shipping two backends" — a set that shrinks — to "a team reviewing agent-written graphics code", a set that grows and does not expire with WebGL2. The demand curve is measured: GitClear's "Maintainability Gap" over **623 million code changes, 2023–2026** — duplicated blocks 40.3 → 73.0 per million changed lines (**+81%**), refactoring **−70%**, copy/paste **+41%**, cross-file reuse **−35%**, legacy maintenance **−74%** (gitclear.com/the_ai_code_quality_maintainability_gap, fetched 2026-09-07). Two honest constraints go into the offer: `semanticDiff` is "a review aid for an emit change, **not** an equivalence proof: it does not compare expression trees" (`shader-dsl/README.md:34`) and must never be sold as one; and every published cell is CI-generated with staleness failing the build (SP §9 R12). Timing is unchanged — line B opens at two external consumers on a tagged release (SP §12.1 Q3).

**Scope and cost, which this defence alone was missing.** **3–4 engineering weeks on top of S1+S2** — a GitHub Action wrapping the four CLI verbs, a PR-comment renderer, a pinned harness image, and the billing/support surface — placed last in §5.2's H2 stack because both its dependencies precede it. **And it does not counter F10; it worsens it.** A paid check is a response-time promise, a second release train and a support obligation, all on the same one person, so S5 is listed against F3 and F6 only, and **F10 is recorded as accepted** (§1): its mitigation is SP §11.7's protocol and SP §9 R2, not this. If S5 ships, R2's likelihood rises with it.

### 3.6 S6 — the published benchmark (ShaderParity-Bench)

**Question, falsifiable:** for an agent asked to ship a shader that runs correctly on **both** WebGPU and WebGL2, does TypeShade produce fewer **semantic** defects per unit of budget than the alternatives?

| Element                                         | Design                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tasks** (n = 40)                              | Tier A "port" (15): an MIT/CC0 GLSL ES 3.00 pair → a working WGSL+GLSL pair, graded against frames from the original — **needs S2's differ, so Tier A is H2**. Tier B "author" (15): a written spec → both targets, graded against a held-out reference. Tier C "precision" (10): tasks where f32 fails visibly (deep zoom, RTC offsets, Mercator at z ≥ 18), graded against an f64 CPU reference. **Tier B and C grade on the existing CPU oracle plus the compile gates**, which is why KR4.4's month-0 tranche (10 Tier-B tasks) can run in H1 with no S2 dependency                                                                                                                                                                             |
| **Arms** (identical budget, unit defined below) | (1) raw hand-written twins · (2) **write WGSL + run naga** · (3) `vgpu` typed WGSL + `vgpu check` + mock runtime · (4) TypeShade. Each in two sub-conditions: **cold** (docs in context only) and **tooled** (a CLI/MCP loop the agent may call) — that split is the experiment's point, separating "the model knows this" from "the model can check this", and it is the only design that distinguishes F1 from F8                                                                                                                                                                                                                                                                                                                                 |
| **Metrics, pre-registered in order**            | (1) semantic-parity pass rate against the held-out reference — **primary** · (2) cross-backend divergence rate (compiles on both, WebGPU ≠ WebGL2) · (3) turns/tokens to first pass — **where TypeShade is expected to lose** · (4) compile-error composition, type vs semantic (the shader-domain re-measurement of the 94% claim) · (5) **silent-wrong rate**: passes the arm's own checks, fails the reference · (6) escape-hatch rate (`rawStmt` / raw strings)                                                                                                                                                                                                                                                                                 |
| **Guards**                                      | Pre-register arms, metrics, N and the kill rule and publish the hash · the grader never runs inside the agent's loop · a **same-arm control** run last establishes the noise floor and is asserted before any between-arm delta is quoted (#2539) · a **known-positive** check plants ≥ 3 real divergences and the grader must catch all three before any zero is believed (#1972) · blinded labels · publish transcripts including the arms TypeShade loses                                                                                                                                                                                                                                                                                        |
| **Persuasive threshold**                        | "TypeShade wins overall" is **not** persuasive — the author built the benchmark. The only publishable shape is a large, mechanism-specific effect **in the condition where competitors have every advantage**: pre-declare that in **tooled**, on Tier A+B, at the pre-registered **4 models × 3 seeds** (120 task×model cells per arm — see the power calculation), TypeShade's cross-backend divergence is **≤ 5% against ≥ 25% for raw and ≤ 15% for translate/vgpu — at least halving the best competing arm with non-overlapping bootstrap CIs — while conceding metric (3)**. Conceding the cost metric is what makes the parity claim credible. On Tier C the bar is **≥ 70% for TypeShade against ≤ 10% for every arm without an f64 path** |
| **Null result, pre-committed**                  | If arm (2) — WGSL + naga — matches TypeShade on metrics (1) and (2), the dual-target thesis is dead and the strategy re-forms around Tier C and the gate alone. **Publishing that is worth more than not running the benchmark**, and it is the cheapest possible test of whether SP §7's real option has value left                                                                                                                                                                                                                                                                                                                                                                                                                                |

**Pre-registration block — the six parameters that were load-bearing and undefined.** All are fixed before run 1, hashed and published with the design above; a run that violates one is discarded, not re-graded.

1. **Budget unit.** Per run: **≤ 25 assistant turns AND ≤ 200,000 total tokens**, whichever binds first. Wall-clock and dollars are explicitly _not_ the unit — tool latency and vendor pricing differ per arm and would confound the comparison the benchmark exists to make. Metric (3) is reported in the same two units.
2. **Models (≥ 3 named, 4 used).** One frontier model per vendor — Anthropic, OpenAI, Google — by exact version string recorded in the pre-registration, **plus one open-weight code model** as the bridge to the only existing proxy: §7's "Not obtained" note stands, no study covers frontier agents on WGSL, and ShaderMatch's 31% figure was measured on > 20 _open_ code models, so without an open-weight arm the two numbers cannot be placed on one axis.
3. **Grader procedure.** Mechanical, run outside the agent's loop, on a pinned harness commit, over arm-anonymised directories. A run passes iff (i) both emits compile — Tint and a real WebGL2 context; (ii) Tier A/B: every one of the task's ≥ 3 fixture states renders within the per-task tolerance of the held-out reference frame, where the tolerance is set by the **same-arm control** (the reference implementation re-run through the same harness), whose floor is asserted before any between-arm delta is quoted (#2539); (iii) Tier C: within a per-task relative-error bound against the f64 CPU reference. Harness failures are logged and re-run, never graded. No human judgement enters the pass/fail channel.
4. **Tier-A corpus and its contamination screen.** The three source repositories are **named in the pre-registration with licence and screen result** — not here, because their licences were not verified in this study. The screen, on the most pretraining-saturated genre in graphics: (a) drop any shader whose source text is retrievable by public code search; (b) **semantically mutate** every retained shader (constant sets, easing curves, channel layouts) and publish the mutation diff, so a memorised copy fails the reference rather than passing it; (c) carry **three unmutated Shadertoy classics as canary positives** — high verbatim recall on those beside failure on their mutated siblings is the screen working, and near-equal scores on both is the screen failing and the tier being void.
5. **Run and API budget.** **2,400 graded runs**: Tier A+B tooled 30 × 3 seeds × 4 models × 4 arms = 1,440; the **cold** sub-condition on the two arms that separate F1 from F8 (raw twins, TypeShade) 30 × 3 × 4 × 2 = 720; Tier C tooled on TypeShade against the best non-f64 arm 10 × 3 × 4 × 2 = 240. Ceiling 480M tokens, expected ≈ one third of that. **The full factorial the earlier design implied — 40 × 5 seeds × 3 models × 4 arms × 2 sub-conditions = 4,800 runs — is cut deliberately**: it doubles the cost for a power gain the calculation below shows is not needed.
6. **Power.** Unit of analysis is the **task × model cell** (seeds are within-cell replicates, not independent observations), so n = 30 × 4 = **120 cells per arm**. Two-proportion z-test, α = 0.05 two-sided: the pre-declared **25% → 5%** effect gives pooled p̂ = 0.15, SE = √(0.15·0.85·2/120) = 0.046, **z ≈ 4.3, power > 0.99**; a **12% → 8%** effect gives SE = 0.039, **z ≈ 1.0, power ≈ 0.18**. Only the pre-declared effect is powered — **if the honest expectation is the smaller one, do not run the benchmark**, and say so instead.

This is also GTM §4.6's **P6** pattern executed — "measured number with methodology … a bare number is an adjective", the bun.sh `reproduce`-link treatment (`docs/design/01-research.md:263`).

# shader-dsl

## Purpose

A zero-dependency TypeScript shader DSL that eliminates hand-maintained GPU/CPU drift. Shaders are authored once as typed node graphs (the IR); the IR is then emitted by THREE backends over ONE shared tree-walk: a **WGSL** writer (production strings for `device.createShaderModule`), a **GLSL ES 3.00** writer (real for render pipelines — vertex+fragment entry-IO + std140 UBO, WebGL2 compile+render-verified; compute/SSBO fail closed), and a **CPU f64 oracle** that tree-walks the same IR on the host for projection math (the generated replacement for the deleted `projection-wgsl-mirror.ts`). Split into `core/` (IR, the neutral emitter + backend contract, the pass pipeline, the SoT layer — all private) and `shaders/` (concrete shader graphs). ⚠️ The `shaders/` graphs were RELOCATED — today they live in `map/src/shaders/dsl/` (#763 A3; an earlier note said `runtime/src/engine/shaders/dsl/`, itself since split into the engine/map packages) and are NO LONGER in this package — the `### Shaders` section below is stale (see docs/architecture/package-responsibilities.md §e). This package is now the content-free `core/` framework; consumers import `core/` via the barrel/subpath.

**Authoring a shader? Read `../AUTHORING.md`** (the package-level guide) — it documents the current
ceremony-free surface (`fn(name, params, body)` with inferred return type, `const x = expr` + `.assign()`,
`If`/`Switch`, the SoT helpers). Several older patterns named below in passing (`Let`/`Var`, `condExpr`) still
exist as primitives, but the guide shows the form to author NEW shaders in.

### Emit core (`core/`)

| File                 | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `core/emit.ts`       | The ONE neutral tree-walk over `Expr`/`Stmt`, shared by every backend (`emitExpr`/`emitStmt`/`emitBody`). Target-neutral: control flow (if/for/switch/return/…) lives here ONCE; only target-specific spelling is delegated to the `Backend`. Backends must NOT re-implement the walk.                                                                                                                                                                                                                                          |
| `core/backend.ts`    | The `Backend` plugin contract: `typeName`/`literal`/`intrinsic` spelling + the handful of divergent declaration fragments (`localLet`/`localVar`/`constDecl`/`caseLabel`/`switchHead`/`rawStmt`/`placeholderStmt`) + a `Capabilities` model. `UnsupportedFeatureError` for fail-closed emit.                                                                                                                                                                                                                                    |
| `core/intrinsics.ts` | Neutral intrinsic-spelling registry (the SoT). Builtins carry a NEUTRAL id (`bitcastU32`, `atan2`, `select`, …); each backend maps id → its own spelling here. Only DIVERGENT intrinsics need an entry; absent = identity `name(args)` (covers portable builtins + user-defined fn calls).                                                                                                                                                                                                                                      |
| `core/oracle.ts`     | `compileModule(IR) → CpuModule`: the CPU f64 tree-walk interpreter (was `backends/cpu.ts`). Uses `cpuValue` constants (full-precision `Math.PI`), or evaluates `valueExpr` via the same tree-walk for non-scalar consts (populated in declaration order, so a later const may reference an earlier one). ⚠️ An f64 **algebra** oracle, NOT an f32-precision oracle — structurally BLIND to f32 GPU rounding bugs (#392, #360). GPU-only stubs (`textureSample`, `fwidth`) return placeholders; `raw`/`placeholder` Stmts throw. |
| `core/diagnostics/`  | Diagnostics layer: `codes.ts` (frozen `SD####` catalogue), `error.ts` (`ShaderDslError`/`dslError` + `SourceLoc`/`formatLoc`), `loc.ts` (opt-in source tracing — `setSourceTracing`, `captureLoc`/`recordLoc`/`getLoc` over a private WeakMap), `report.ts` (`diagnose()`/`formatReport()`). `ValidationError`/`UnsupportedFeatureError` subclass `ShaderDslError`.                                                                                                                                                             |
| `core/sot.ts`        | Single source of truth for IO structs & bound resources (was `schema.ts`). `ioStruct`/`structDecl`/`uniformStruct`/`resource`/`storageBuffer` declare a layout ONCE and DERIVE the StructDecl + binding + typed field access, so the pieces cannot drift (the polygon slot-drift / OPACITY bug class). Wrong field name/type is a `tsc` error.                                                                                                                                                                                  |

| File                    | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## For AI Agents

### Working In This Directory

- **One IR, three backends over ONE walk.** Control flow (if/for/switch/return/…) is emitted ONCE in `core/emit.ts`; a backend only supplies type/literal/intrinsic spelling + the divergent declaration fragments (`core/backend.ts`). Adding a target = implement `Backend`, never fork the walk. A new divergent intrinsic = one entry in `core/intrinsics.ts`, not a per-backend rename table.
- **Mutability is a TYPE distinction: `Node` (mutable, has `.assign`) vs `ReadonlyNode` (its supertype, no `.assign`).** `Var()` and every value-PRODUCER (literals, ctors, arithmetic, accessors, builtins) return `Node`; `Let()` / a function param / a module const return `ReadonlyNode`, so `someLet.assign(…)` / `param.assign(…)` is now a **`tsc` compile error** (was only the `no-assign-to-let` lint rule, caught at emit). Read-APIs (builtins, `.of`, `fn` return, `Return`) accept the `ReadonlyNode` supertype, so an immutable binding flows everywhere a value is read. This is a TYPE-LEVEL split only — the runtime is one class, so emitted WGSL/GLSL is byte-identical (mirrors RxJS `Observable` vs `Subject`). The `const x = expr; x.assign(…)` auto-var pattern still works (produced values are `Node`) and is materialised into a real `var` by `autoVars`, which runs on ALL THREE backends — never skip it on a new backend. `no-assign-to-let` remains as a defence-in-depth lint (catches member-of-let, which the type split does not).
- **Never "unify" `PI`/`DEG2RAD` constants.** `ConstDecl` has separate `wgslValue` (truncated shader literal) and `cpuValue` (full-precision `Math.PI`). Merging them injects ~5–10 m drift (render gate) or breaks the ≤1 mm CPU parity gate.
- **`project_geom` vs `project_geom_cpu` differ on purpose.** The GPU version applies a world-copy offset per-vertex; the CPU version omits it because consumers telescope the offset out. Do not "fix" this divergence.
- **`matchExpr` Exprs must never reach `emitExpr` directly.** `emitModule` runs `lowerModule` (`passes/match-lower.ts`) first to hoist them into `var` + `switch` pairs. If `matchExpr` leaks to `emitExpr`, it throws loudly.
- **`placeholder` Stmts must be swapped by the polygon composer before GPU emit.** An un-swapped placeholder emits a WGSL comment (no-op, silent) on the GPU side but throws on the CPU oracle — the asymmetry is intentional and load-bearing.
- **`raw` Stmts are GPU-only.** The CPU oracle and the GLSL backend throw on them. Do not add `raw` Stmts on code paths that also run through `cpu-projections.ts`, compute evaluation, or GLSL emit.
- **AC4 type safety is enforced by `tsc`, not by `bun run build`.** Gate phantom-type changes with `bunx tsc -p shader-dsl/tsconfig.json --noEmit`.
- **Polygon `Uniforms` struct is 272 bytes (reflect-derived via `polygonUniformSlots()` — never hardcoded), field order is load-bearing.** Reordering fields silently mis-binds GPU reads in every per-tile `writeBuffer` caller.
- **Source-location side-table is AUTHORED-MODULE-ONLY + emit-neutral.** `core/diagnostics/loc.ts` keys locations by Stmt/FuncDecl OBJECT IDENTITY in a WeakMap — never an IR field, so emit is byte-identical (capture also defaults OFF and is zero-cost). `getLoc` resolves only on the authored module; `autoVars`/`lowerModule`/`cse` rebuild every node and break identity, so never call `getLoc` on a lowered module. `validate()`/`lintModule()`/`diagnose()` run pre-lowering, which is why their diagnostics can carry a `loc`.
- **Consumers import only from `../shader-dsl` (the barrel).** The non-barrel modules (above) are direct internal imports — do not add one to the barrel without coordinating with all renderers.

### Common Patterns

- **Single-source three-backend authoring**: every shader function is written once with `fn(name, params, retType, (p, b) => { … })`. The WGSL backend emits the GPU string, the GLSL backend a WebGL2 string, the CPU oracle tree-walks the same IR.
- **`Node<K>` chaining**: arithmetic, comparisons, swizzles, builtins chain on `Node` (`a.add(b)`, `a.lt(b)`, `node.field('x', f32T)`). The phantom key `K` carries the WGSL type; mismatches are `tsc` errors.
- **SoT layout declarations**: declare an IO/uniform/storage layout ONCE via `core/sot.ts` (`ioStruct`/`uniformStruct`/`structDecl`/`resource`/`storageBuffer`) and derive the StructDecl + binding + typed field access (replaces the old `schema.ts` `struct()`).
- **`ConstDecl` dual-value**: every constant needing CPU/GPU fidelity uses `{ wgslValue: <truncated>, cpuValue: <Math.*> }`.
- **Projection dispatch from table**: `PROJECTIONS` in `projection/projections-table.ts` is the single source of truth; do not add a projection without a table entry.
- **Placeholder + composer**: `polygon.ts` lays down `b.placeholder('fill-return')`; the first-class `composeModule(base, swaps)` pass (`core/passes/compose.ts`) swaps each tagged placeholder before `emitModule`, descending into nested bodies. STRICT by default — an un-swapped placeholder or a typo'd swap key throws (pass `{ allowUnswapped: true }` for deliberate bare survival). Replaced the former hand-rolled per-shader `swapPlaceholders` walk.

## Dependencies

### Internal

- `engine/src/projection/projections-table.ts` — projection registry; drives the dispatch ladder in `map/src/shaders/dsl/projections.ts` (#763 A3 — both paths moved in the engine/map split)

### External
